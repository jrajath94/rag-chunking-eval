# EXECUTION: runbook for the RAG chunking evaluation

Run everything from the repo root: `~/workspace/rag-chunking-eval`. Use
`.venv/bin/python` directly in each command so they paste cleanly without
activating the venv first.

## 0. One-time setup

Fresh install (do torch first, CPU wheel only, then the rest):

```bash
cd ~/workspace/rag-chunking-eval
mkdir -p ~/pip-tmp
python3 -m venv .venv
TMPDIR=~/pip-tmp .venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
TMPDIR=~/pip-tmp .venv/bin/pip install -r requirements.txt
.venv/bin/pip freeze > results/RUNINFO.md
```

Notes:

- TMPDIR is mandatory. `/tmp` on this box is a 512 MB tmpfs and pip fails
  without it. This rule applies to every pip call, forever.
- `requirements.txt` does not include torch. If torch comes from plain PyPI
  it pulls a CUDA wheel (gigabytes of dead weight on a CPU-only box).
- This repo already has a working `.venv` (Python 3.12.3, torch 2.14.0+cpu,
  verified Sept 28, 2026). If yours works, skip straight to step 1 and just
  refresh `results/RUNINFO.md`.
- The run script strips bracketed IPv6 literals out of no_proxy/NO_PROXY at
  startup. That is a workaround for httpx 0.28 on this box, not something
  you need to do by hand.

## 3. Synthetic sanity (stage A)

```bash
cd ~/workspace/rag-chunking-eval
.venv/bin/python scripts/run_experiment.py --stages A
```

What it does: builds the 20-document / 40-question synthetic corpus in memory
(seed=7), embeds with the real `all-MiniLM-L6-v2`, runs all four strategies,
and writes:

- `results/synthetic_real_embedder.json` (per-strategy recall summary)
- `results/synthetic_check.md` (predicted ordering from TRD Section 8 vs
  the actual synthetic ordering, timestamped)

Read `results/synthetic_check.md`. A four-way tie at recall@5 = 1.000 is a
known possible outcome: the toy corpus is too easy to discriminate
strategies. A tie neither confirms nor falsifies the prediction. Move on to
stage B either way; the prediction is never adjusted after the fact.

## 4. SQuAD slice, generation, judging, report (stages B-E)

Full run, all stages:

```bash
cd ~/workspace/rag-chunking-eval
.venv/bin/python scripts/run_experiment.py
```

Or a subset: `--stages B`, `--stages C,D`, etc. Each stage overwrites its
own outputs and is resumable. Stages in order:

- **B**: downloads the SQuAD 2.0 dev set once from
  `https://rajpurkar.github.io/SQuAD-explorer/dataset/dev-v2.0.json` into
  `.data/` (raw data stays out of git; later runs reuse the cache), takes 60
  answerable questions in deterministic order, chunks + retrieves k=5 per
  strategy, writes `results/squad_slice.json` and `results/retrieval.json`
  (240 records: 60 questions x 4 strategies).
- **C**: generates answers with `google/flan-t5-base`, greedy
  (`do_sample=False`, `max_new_tokens=64`). Generation context is cut to 450
  tokens with the T5 tokenizer when too long; truncations are counted per
  strategy. Writes `results/answers.json`. This is the slow stage on CPU:
  240 generations, sequential. Do not parallelize it naively on a 2-core box.
- **D**: judges faithfulness with `cross-encoder/nli-deberta-v3-small`.
  Premise cut to 400 tokens with the NLI tokenizer. Label indices come from
  `model.config.id2label` at runtime (never hardcoded). Supported means
  P(entailment) >= 0.5 and P(contradiction) < 0.5. Empty answers get
  `faithfulness = None` (counted, excluded, never scored as zero). Writes
  `results/results.json` with a `run` block (models, date, wall time) plus
  the 240 final records.
- **E**: writes `results/summary.csv`, `results/RESULTS.md`,
  `results/recall.png`, `results/faithfulness.png`. The PNGs sit flat in
  `results/`, not in a `plots/` subdirectory. `RESULTS.md` is generated by
  the script, not written by hand: it contains the date, models, versions,
  k=5, truncation policy, the predicted ordering, both actual orderings
  (recall and faithfulness), the per-strategy table, and the limits list.

## 5. Independent verification

The analysis script checks data invariants from scratch and reports
predicted-vs-actual ordering. It uses stdlib only and does not import the
package, so it verifies the pipeline instead of repeating it.

```bash
cd ~/workspace/rag-chunking-eval
.venv/bin/python scripts/analyze_results.py
```

It exits 0 when every invariant holds (recall in [0,1], exactly k=5
retrieved ids per record, n_supported <= n_claims, faithfulness arithmetic
matches, equal n per strategy, no duplicate question ids).

KNOWN BUG (Sept 28, 2026): `analyze_results.py` expects a bare JSON list of
records, but stage D writes `results.json` as `{"run": {...}, "records": [...]
}`. Until the script is fixed, extract the records first:

```bash
cd ~/workspace/rag-chunking-eval
.venv/bin/python -c "import json; d=json.load(open('results/results.json')); json.dump(d['records'], open('/tmp/records.json','w'))"
.venv/bin/python scripts/analyze_results.py --results /tmp/records.json
```

The script fix (accept the `{"run","records"}` envelope) is one open item
before the verification gate can run as written.

## 8. Re-run and rollback checklist

Before any fresh long run:

- `pytest` green (step 1).
- `configs/strategies.yaml` unchanged since the last run (check `git diff`).
- `.data/dev-v2.0.json` present or the SQuAD URL reachable (step 4).
- Pre-flight checklist green (TRD Section 13).

Rollback: every phase ends in an atomic git commit. To roll back, revert to
the last green commit (`git revert` or `git checkout <commit> -- .`). The
derived files regenerate from `results.json` + `configs/strategies.yaml`
via step 7. Regenerating `results.json` itself means re-running stages B-D,
which is the long part; there is no shortcut for that.
